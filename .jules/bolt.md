
## 2024-05-18 - IPC Timer Optimization
**Learning:** The `xdw_get_sys_time_ms` function (which actually returns microseconds) in the `airplay2-win` socket IPC component used the two-step `GetSystemTime` and `SystemTimeToFileTime` combination intended as a Windows CE fallback for retrieving the current time. This involves parsing the time into a structure (calendar math) only to encode it right back into an epoch format. Furthermore, it redundantly unpacked the epoch microseconds into separate seconds and microseconds in a `timeval` structure, and then instantly re-multiplying and adding them to return a flat 64-bit integer, wasting CPU cycles on a highly accessed hot path (IPC message queuing).
**Action:** When inspecting legacy codebase timers and epoch generation code, always evaluate if a direct high-resolution system call (like `GetSystemTimeAsFileTime`) can replace calendar-based API calls (`GetSystemTime`), and remove any intermediate structure conversion (like `timeval` creation) if the final result is just an integer representation.
